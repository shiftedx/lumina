# ADR 0034: Retain native artwork in a private device cache

The owner requested fast, visually complete Library returns and persistent on-device artwork with an explicit clear control. iOS and tvOS retain validated compressed artwork in a disposable 2 GiB device cache, alongside bounded decoded and compressed memory tiers, rather than refetching visited posters after memory eviction or every app launch.

Disk work runs off the main actor. File names hash the complete signed rendition URL, including its artwork tag and requested size; raw signed URLs and credentials are not written into cache metadata. An LRU index bounds storage without rescanning the directory after every write. Corrupt entries are discarded and fetched again. The OS may reclaim cache files. The cache directory is excluded from backups and uses platform file protection where supported.

Initial restoration of the same session may reuse its disk renditions. Actual member, server or credential changes discard resident artwork and invalidate pending disk writes before purging prior cache data. Device settings show retained bytes and provide an asynchronous Clear artwork cache action on both platforms. Clearing cancels old work so a late response cannot recreate deleted files. This cache stores visual renditions, not playable downloads or credentials, and never grants access to server media.

The Library retains a bounded set of in-process query snapshots, including loaded pages, cursors and alphabet anchors. The store owns the current query and shares repeated requests for it, so cancellation of a view's appearance task during navigation cannot strand the previous category on screen. A newer query or session change still cancels obsolete work. Explicit refresh and account/activity changes obtain fresh server state. Returning to a pushed Library root preserves its visible artwork and navigation identity; fresh walls prepare a viewport of images before publication. This trades local storage and bounded RAM for fewer requests and avoids exposing a partially repopulated grid during navigation. It adds no server schema or full-library background backfill.
