# Native Apple apps

Source updates and small UI changes do not trigger a TestFlight release. For explicitly requested signed device testing through TestFlight, use the [native distribution guide](docs/testflight.md). iOS and tvOS share one Lumina app record. Distribution defaults to internal testing; external candidates require an explicit export option and Apple's beta review.

SwiftUI applications for iPhone, iPad, and Apple TV, sharing a Foundation API client and an AVKit video player. These are native apps; they contain no web view. Home and the media libraries browse the household's existing Lumina server. Direct and compatible HLS video synchronize watch progress with the web UI; music uses authenticated native audio streams.

The shared [Lumina brand identity contract](docs/brand-assets.md) defines the approved sunrise assets, adaptive native/web control roles, and the change/verification procedure.

This is an engineering proof, not an App Store release or an Infuse playback replacement. AI discovery, profile switching, PiP, acquisition, administration, and third-party streaming services are outside this proof. Native AVKit audio/subtitle controls expose the tracks present in the selected stream; full library subtitle delivery and premium codec parity still need implementation and device qualification.

## Build and install

Requires Xcode 26 or newer with iOS/tvOS SDKs, a Mac, and iOS/iPadOS/tvOS 18 or newer. The checked-in Xcode project was generated with XcodeGen; ordinary Xcode builds do not require XcodeGen.

1. Open `apple/Lumina.xcodeproj`.
2. Select **Lumina-iOS** or **Lumina-tvOS**, then a simulator or paired physical device.
3. For a physical device, select your Apple development team under **Signing & Capabilities**. Change the bundle identifier if your team requires it. No developer credentials are stored in this repository.
4. Build and run. Allow local-network access when iOS asks.
5. Open **Mobile connect** in the web account menu and scan its QR in the iOS/iPadOS app. Owners can enable mobile access from that dialog. Personal codes expire after five minutes and work once; owner-shared codes last fifteen minutes. The app creates a revocable device sign-in when it claims the code. **Advanced** reveals manual server/account entry, also available when camera access is unavailable. Manual server addresses must have no `/jellyfin` or `/emby` suffix; accounts with two-step verification use an app password.

Use the existing server's remote HTTPS or explicitly configured LAN HTTP address. Do not expose the internal Docker service port for remote use. The app uses Apple’s [local-network ATS exceptions](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking) for local names, `.home.arpa`/`.lan` names, and private IP ranges and keeps normal TLS validation; remote servers should use trusted HTTPS. Server addresses must be origins without a path, query, or embedded credentials. Session tokens and a stable device ID use Keychain device-only After First Unlock protection; existing entries migrate in place when read. The password is used only to exchange for a revocable connected-app token. Sign-out clears the local session immediately, retains the stable device ID, and attempts server revocation; an offline token can also be revoked through Lumina's Connected apps page.

```sh
cd apple
swift test --package-path Core
xcodebuild -project Lumina.xcodeproj -scheme Lumina-iOS \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Lumina.xcodeproj -scheme Lumina-tvOS \
  -destination 'generic/platform=tvOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

After changing `project.yml`, run `xcodegen generate` from `apple/` and commit the regenerated project. `LuminaCore` is a local Swift package with no external dependencies.

## Browsing

Home opens with a responsive featured carousel, Continue watching, Next up, and recently added media. Compact layouts retain full-height artwork behind the hero controls; wide layouts retain cinematic copy over artwork. Portrait-only artwork keeps its proportions against a diffuse backdrop. iOS and tvOS library and Requests heroes share the web server’s cached face/subject analysis, preserving headroom and moving off-center subjects into the visible crop. Framing loads alongside the artwork with a 150 ms request timeout; pending analysis or an older server uses the conservative upper crop, and the displayed image stays stable until its source changes. Shape-specific rails give landscape stills more width than posters and use inset-aligned ruled headings. The bundled [Newsreader fonts](Fonts/README.md) bring the web gallery's editorial title and chapter hierarchy to native layouts while supporting text-size scaling. Slides move horizontally, with previous/next controls and touch swipes. Rotation advances every eight seconds while idle and pauses during interaction, in the background, or when explicitly paused. Reduce Motion and VoiceOver disable automatic rotation. Home's selections stay independent of Video searches and Audio browsing.

iPhone and iPad use system navigation for Home, Library, Requests and Account. Library groups Movies, TV, Anime, Music and Books, while the system adapts navigation placement to the display. Artwork extends behind the navigation chrome. iOS starts in the gallery's dark appearance. Account opens device-focused settings with inline gold-underlined choices for appearance, video quality, audio language and subtitles, plus downloads and Home layout. These playback and appearance overrides stay on this installation. Episodes and seasons inherit their series poster when they have no artwork of their own; their own artwork takes precedence. On Apple TV, focusing any hero action pauses rotation, and the bounded title controls share a single remote-navigable row.

iOS movie and series details open with a full-viewport artwork hero. Play/Resume and watchlist remain on the artwork; series offer a Seasons control that scrolls to the collection below. Synopsis, cast, and related titles follow below the hero. Detail artwork uses a bottom readability gradient instead of a blanket lateral scrim, and detail headers omit Lumina branding while navigation roots retain it.

Movie filters include resolution (4K, 1080p, 720p, SD), HDR type (SDR, HDR10, HDR10+, Dolby Vision, HLG), IMAX edition and audio format (Atmos, TrueHD, DTS-HD, DTS, Dolby Digital/Plus, AAC). The connected server filters visible files before paging and alphabetical indexing, with all selected technical properties required on the same version. IMAX requires an explicit filename/edition marker; HDR and audio use cached probe facts. Unknown metadata is not guessed, and older HDR caches need normal re-probing before the added HDR detail is available. The native sheet enables these choices only when the server advertises the technical-filter contract. TV-series browsing retains the existing genre, year and activity filters.

Verified admins also get library scans, library activity and viewer invitations. Invitation creation and revocation require fresh password/second-factor verification; invitation links are shared explicitly, and library access starts unselected. These quick actions require the server's native admin Settings adapters. Watch-history import, integrations and account/security administration remain on the website, reachable through the native Account and Manage server links.

Home’s top row links to Movies, TV, Anime, Music and Books, with Watchlist last; All and Watchlist refine Home in place. Genre refinement belongs in the primary library views. Apple TV omits Books because its native reader is iOS-only.

Apple TV uses one persistent header: Lumina branding, All / Movies / TV / Anime / Music / Watchlist, and quiet Search, Requests and Account utility icons. There is no second top-level navigation row; music collection and browse controls sit below its hero. All and Watchlist show Home; media categories open their libraries. Home and Music feature artwork beneath this header, and library poster captions appear on focus. Gold marks the selected route; ordinary controls remain neutral.

Native video and music grids warm the next 16 artwork renditions through a shared, bounded session cache. Decoded hits display immediately on return; compressed renditions avoid repeat downloads after decoded-image eviction. Visible and speculative artwork share four active load slots, and abandoned consumers cancel their work. The cache targets 64 MiB decoded and 32 MiB compressed storage and clears on session changes. It does not persist artwork to disk. See [cache measurements and limits](docs/performance-review.md#large-library-artwork-retention-2026-10-24).

Video provides search, films/shows/anime/episode categories, name/year/recent sorting, and a paginated poster catalog. All groups television into shows; individual episodes have their own category. Shows open into seasons and ordered episodes. Search ranks results by relevance. Filters combine genre, year, unwatched, and favorites; title details synchronize watched and favorite actions with the server. On iOS, search is available from the toolbar or a short pull; a longer pull refreshes. Sign-out is inside Account. Apple TV uses focusable category controls, native focus effects, and remote transport controls.

Audio browses albums, artists, and tracks, including square artwork and ordered collections. Albums use a cover-and-track two-column layout at regular widths, with a centered cover and single-column content on compact or accessibility-size layouts. Roman editorial album titles, ruled numbered tracks and actual durations distinguish the listening view from the video poster catalog. Play album and Shuffle open a listening screen with artwork, seeking, play/pause, previous/next tracks, repeat, and an editable play queue. Browse returns to the library while a compact Now Playing bar keeps music accessible across destinations; Stop ends the listening session. Music continues in the background and exposes system Now Playing controls. Starting video stops music. Tracks synchronize listening positions through the same connected-app session. Music requires a server with the additive music compatibility endpoints. Supported source formats play directly; other containers use the server's bounded FLAC conversion cache through the authenticated audio endpoint.

Audio also provides saved and smart playlist creation, editing and deletion, shared household playlists with read-only access for other members, and server-generated mixes. The member-owned listening queue synchronizes using revision checks; a conflict offers **Use server** or **Keep this device** rather than silently overwriting another device. Owner-scoped checkpoints restore the queue and position paused after relaunch. Queue synchronization is per member, not a multi-member listening party.

Open **Downloads** or use **Download music** in the player to save tracks, an album, or a queue. The shared device download budget is 64 GiB, with a 128 MiB audio-file cap, 32 GiB video-file cap and 2 MiB artwork cap. Space is used only for explicitly requested downloads. Downloads run sequentially with progress, cancel, retry, remove and clear controls; no track is silently evicted. Successful native files are checked locally for playability; an unsupported saved file is retried as WAV. Authentication failures do not trigger compatibility retries. A retained authenticated session can play local files without the network; sign-out clears that member's downloads. iOS uses Application Support; tvOS uses purgeable Caches, so Apple TV downloads may need saving again. Cached manifests contain metadata and local filenames, not stream URLs or tokens.

The player shows lyric source and timed lyrics when supplied; selecting a timed line seeks playback. Buffered playback applies manual gain or album/track normalization with peak limiting. It retains only bounded current/next-track PCM at 48 kHz stereo and schedules gapless transitions on the native audio clock, with crossfade choices **Off**, **3**, **6**, or **12 seconds**. Sources outside the buffering budget or decoder support fall back to streaming with an explicit source-loudness label; normalization and crossfade are unavailable on that path. The sleep timer stores an owner-scoped deadline, and interruptions or headphone removal pause local playback.

**Audio output** offers AirPlay and Chromecast on iOS with Lumina's shared SVG controls. AirPlay uses the native audio route picker and retains local queue ownership. Chromecast projects up to 100 upcoming queue occurrences into the receiver so playback can advance while the phone sleeps; the player displays the queue limit when it truncates a longer queue. Receiver media uses device-bound, per-item scoped links and lazy AAC-LC stereo M4A conversion (192 kb/s, 48 kHz). Local audio pauses only after the receiver acknowledges the live position and intent; transport and volume then control that receiver. Returning playback requires an owned receiver's stop acknowledgement. Queue editing, local normalization, crossfade, repeat and sleep options remain unavailable during Cast ownership. Previously started remote speaker output retains its stop/return path. tvOS uses its system output controls. Physical AirPlay/Chromecast behavior still requires receiver qualification; see [verification](docs/verification.md).

## Playback behavior

On iOS, **Playback settings → Info → Playback diagnostics → Start recording** enables a local capture for up to five minutes. Return to the movie, reproduce the issue, then choose **Finish recording → Share diagnostics**. Save the JSONL file to Files or share it through the system sheet; nothing is uploaded automatically. The capture follows player/presentation replacement and remains available after relaunch. If recording was interrupted, share the saved portion. **Start new recording** replaces the previous capture; **Delete recording** removes it.

The export contains numeric playback clocks, buffering, seeks and results, lifecycle and renderer events, opaque process-local object identifiers, app/build/OS versions, and sanitized error domains/codes. It excludes media titles, source URLs, account details, credentials, and raw native access/error-log payloads. Capture storage is excluded from backup, bounded to 1 MiB/2,000 records, and written off the playback thread. Frequent sample/layout events are limited so they leave room for native time-jump and transport evidence. Diagnostics help investigate physical-device failures; enabling them does not itself fix playback or establish seamless folding.

Direct playback is negotiated for native MP4/M4V/MOV H.264 (8-bit)/HEVC (up to 10-bit) and AAC/AC-3/E-AC-3/MP3/ALAC. MP3 and ALAC additions have synthetic macOS AVPlayer decode evidence; per-device output qualification is still required. Other sources use the server's HLS path when supported. On tvOS, **Convert to compatible video** disables direct playback and asks the server for a compatible stream; the server may retain compatible video while converting audio. Conversion does not promise source HDR, Dolby Vision, lossless audio, or Atmos preservation.

On iOS, a movie or episode's overflow offers **Download to Device**. Complete MP4/M4V/MOV and MKV files are retained with artwork and local resume position; local MKV playback uses PrismCore. Completed downloads survive app termination and restart. Incomplete transfers are never advertised as playable; they can be retried after interruption. Downloads stay private to the current server/member and sign-out removes them.

Device network-path changes and real server connection failures select an **On this device** surface showing only complete local media. A retained session can open that surface immediately on an offline cold launch without server validation. Reconnect and foreground activation revalidate the server before restoring remote browsing. Airplane mode with usable Wi-Fi remains online. Cached artwork and metadata alone do not make a streamed video available offline. Embedded subtitles remain part of the original file; network-only sidecar subtitles are not downloaded.

On iOS, the root video session owns the player and its startup task above adaptive navigation. Rebuilding the player presentation retains the live item and playback position; only explicit dismissal or sign-out ends the session. The presentation-rebuild UI workflow checks playing and paused sessions for both native direct and client-demux delivery. Physical Duo testing remains necessary to qualify the actual display handoff.

The iOS video overlay uses the shared Lumina SVG family with plain controls: Close/PiP and audio above, transport centered, and metadata, timeline, settings, AirPlay and Chromecast below. AirPlay opens Apple's video route picker. Chromecast uses the exactly pinned Google Cast iOS SDK 4.8.6 and its default media receiver; discovery starts only after tapping Cast, SDK analytics/logging are disabled, and its bundled privacy manifest and third-party notices accompany the dependency.

Native Chromecast requires the matching server update, a server address reachable from the receiver, and the server's existing conversion capacity/policies. Compatible H.264/AAC MP4 video remains direct; other supported sources use server HLS with a 1080p H.264/stereo AAC receiver profile. The exact loaded media version and selected source tracks are retained. Receiver URLs carry revocable device-bound capabilities, never the app credential; HLS child requests use that same scoped capability. Local playback continues until the receiver acknowledges the live position and play/pause intent. Return waits for an owned receiver's stop acknowledgement; a disconnected receiver requires an explicit Return action. Casting retains the root playback model and does not change the fold lifecycle. Simulator and contract tests cannot establish physical Chromecast/AirPlay compatibility; qualify actual receiver playback, background continuity and return on hardware before release.


The player seeks to the saved whole-file position before reporting start, sends progress about every five seconds and on transport state changes, and sends a final stopped event on dismissal. Reports are serialized so a delayed progress request cannot overwrite the stopped position. Leaving the app pauses video; music continues in the background. Stopping also releases the server's HLS session. A network failure displays a progress-sync warning. The audio engine schedules native file segments with bounded priming instead of allocating whole source/converted PCM buffers or copying a seek slice. Normalization, the existing stereo engine output and clock-scheduled crossfade remain active. Remote playback in queues with qualified source codecs, admitted metadata, crossfade off and unity effective gains use a private progressive range loader and AVQueuePlayer, starting before complete delivery. The engine and its gain units are created only when processing is needed. Enabling crossfade or a non-unity normalization gain switches that occurrence to the engine while retaining position; its bounded input still downloads completely and stays private until its prepared slot is released. Ordinary music pause/resume retains the current native player or prepared file slots without resolving, downloading or converting the track again; the app playback clock and decoded engine are paused. Stop, track replacement, sign-out and terminal failure release these resources. Music keeps an owner-scoped local queue checkpoint and exposes synchronization conflicts when the server becomes reachable. Active progressive playback controls read-ahead using native buffered time, with a reserve for queued-track preroll. Source position comes from the native player clock. Pausing suspends progressive HTTP read-ahead for the current and queued track; resume retains both assets. A paused seek permits only the current asset to fetch needed bytes until seeking completes.

The TV music player opens on full-screen artwork with a bottom timeline and a persistent Queue / Play-Pause / Repeat / Stop rail. Left and Right while artwork owns focus change queued tracks; Down enters the rail and lower options. Lyrics and listening options start collapsed. Hardware Play/Pause remains available, and Back unwinds the queue or player before leaving its browsing context.

Apple TV uses the native focus engine, remote transport controls, a readable poster grid, and native playback controls, following Apple's [tvOS design](https://developer.apple.com/design/human-interface-guidelines/designing-for-tvos), [focus](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection), and [video playback](https://developer.apple.com/design/human-interface-guidelines/playing-video) guidance. AVKit's preferred display criteria are enabled for the system's Match Content behavior. Actual HDR, refresh-rate switching, HDMI output, and multichannel sound must be checked on hardware; simulator playback cannot establish them.
