# Native Apple apps

Source updates and small UI changes do not trigger a TestFlight release. For explicitly requested signed device testing through TestFlight, use the [native distribution guide](docs/testflight.md). iOS and tvOS share one Lumina app record. Distribution defaults to internal testing; external candidates require an explicit export option and Apple's beta review.

SwiftUI applications for iPhone, iPad, and Apple TV, sharing a Foundation API client and an AVKit video player. These are native apps; they contain no web view. Home and the media libraries browse the household's existing Lumina server. Direct and compatible HLS video synchronize watch progress with the web UI; music uses authenticated native audio streams.

This is an engineering proof, not an App Store release or an Infuse playback replacement. AI discovery, profile switching, PiP, acquisition, administration, and third-party streaming services are outside this proof. Native AVKit audio/subtitle controls expose the tracks present in the selected stream; full library subtitle delivery and premium codec parity still need implementation and device qualification.

## Build and install

Requires Xcode 26 or newer with iOS/tvOS SDKs, a Mac, and iOS/iPadOS/tvOS 18 or newer. The checked-in Xcode project was generated with XcodeGen; ordinary Xcode builds do not require XcodeGen.

1. Open `apple/Lumina.xcodeproj`.
2. Select **Lumina-iOS** or **Lumina-tvOS**, then a simulator or paired physical device.
3. For a physical device, select your Apple development team under **Signing & Capabilities**. Change the bundle identifier if your team requires it. No developer credentials are stored in this repository.
4. Build and run. Allow local-network access when iOS asks.
5. Enable **Manage Server → Connections → Metadata → Apps like Infuse** in Lumina's web UI. Enter the server origin shown there, with no `/jellyfin` or `/emby` suffix. Use the member's own Lumina account; accounts with two-step verification must use an app password.

Use the existing server's remote HTTPS or explicitly configured LAN HTTP address. Do not expose the internal Docker service port for remote use. The app uses Apple’s [local-network ATS exceptions](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking) for local names, `.home.arpa`/`.lan` names, and private IP ranges and keeps normal TLS validation; remote servers should use trusted HTTPS. Server addresses must be origins without a path, query, or embedded credentials. Session tokens and a stable device ID are stored in Keychain; the password is used only to exchange for a revocable connected-app token. Sign-out clears local credentials immediately and attempts server revocation; an offline token can also be revoked through Lumina's Connected apps page.

```sh
cd apple
swift test --package-path Core
xcodebuild -project Lumina.xcodeproj -scheme Lumina-iOS \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Lumina.xcodeproj -scheme Lumina-tvOS \
  -destination 'generic/platform=tvOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

After changing `project.yml`, run `xcodegen generate` from `apple/` and commit the regenerated project. `LuminaCore` is a local Swift package with no external dependencies.

## Browsing

Home opens with a responsive featured carousel, Continue watching, Next up, and recently added media. Compact layouts place 16:9 artwork above paper-and-ink copy; wide layouts retain cinematic copy over artwork. Portrait-only artwork keeps its proportions against a diffuse backdrop. iOS and tvOS library and Requests heroes share the web server’s cached face/subject analysis, preserving headroom and moving off-center subjects into the visible crop. Framing loads alongside the artwork with a 150 ms request timeout; pending analysis or an older server uses the conservative upper crop, and the displayed image stays stable until its source changes. Shape-specific rails give landscape stills more width than posters and use inset-aligned ruled headings. The bundled [Newsreader fonts](Fonts/README.md) bring the web gallery's editorial title and chapter hierarchy to native layouts while supporting text-size scaling. Slides move horizontally, with previous/next controls and touch swipes. Rotation advances every eight seconds while idle and pauses during interaction, in the background, or when explicitly paused. Reduce Motion and VoiceOver disable automatic rotation. Home's selections stay independent of Video searches and Audio browsing.

iPhone and iPad use system navigation for Home, Library, Requests and Account. Library groups Movies, TV, Anime, Music and Books, while the system adapts navigation placement to the display. Artwork extends behind the navigation chrome. iOS starts in the gallery's dark appearance. Account → Appearance offers Dark, Light, and System. Episodes and seasons inherit their series poster when they have no artwork of their own; their own artwork takes precedence. On Apple TV, focusing any hero action pauses rotation, and the bounded title controls share a single remote-navigable row.

Home’s top row links to Movies, TV, Anime, Music and Books, with Watchlist last; All and Watchlist refine Home in place. Genre refinement belongs in the primary library views. Apple TV omits Books because its native reader is iOS-only.

Apple TV uses one persistent header: Lumina branding, All / Movies / TV / Anime / Music / Watchlist, and quiet Search, Requests and Account utility icons. There is no second top-level navigation row; music collection and browse controls sit below its hero. All and Watchlist show Home; media categories open their libraries. Home and Music feature artwork beneath this header, and library poster captions appear on focus. Gold marks the selected route; ordinary controls remain neutral.

Native video and music grids warm the next 16 artwork renditions through a shared, bounded session cache. Decoded hits display immediately on return; compressed renditions avoid repeat downloads after decoded-image eviction. The cache targets 64 MiB decoded and 32 MiB compressed storage, loads at most four speculative images at once, and clears on session changes. It does not persist artwork to disk. See [cache measurements and limits](docs/performance-review.md#large-library-artwork-retention-2026-10-24).

Video provides search, films/shows/anime/episode categories, name/year/recent sorting, and a paginated poster catalog. All groups television into shows; individual episodes have their own category. Shows open into seasons and ordered episodes. Search ranks results by relevance. Filters combine genre, year, unwatched, and favorites; title details synchronize watched and favorite actions with the server. On iOS, search is available from the toolbar or a short pull; a longer pull refreshes. Sign-out is inside Account. Apple TV uses focusable category controls, native focus effects, and remote transport controls.

Audio browses albums, artists, and tracks, including square artwork and ordered collections. Albums use a cover-and-track two-column layout at regular widths, with a centered cover and single-column content on compact or accessibility-size layouts. Roman editorial album titles, ruled numbered tracks and actual durations distinguish the listening view from the video poster catalog. Play album and Shuffle open a listening screen with artwork, seeking, play/pause, previous/next tracks, repeat, and an editable play queue. Browse returns to the library while a compact Now Playing bar keeps music accessible across destinations; Stop ends the listening session. Music continues in the background and exposes system Now Playing controls. Starting video stops music. Tracks synchronize listening positions through the same connected-app session. Music requires a server with the additive music compatibility endpoints. Supported source formats play directly; other containers use the server's bounded FLAC conversion cache through the authenticated audio endpoint.

Audio also provides saved and smart playlist creation, editing and deletion, shared household playlists with read-only access for other members, and server-generated mixes. The member-owned listening queue synchronizes using revision checks; a conflict offers **Use server** or **Keep this device** rather than silently overwriting another device. Owner-scoped checkpoints restore the queue and position paused after relaunch. Queue synchronization is per member, not a multi-member listening party.

Open **Downloads** or use **Download music** in the player to save tracks, an album, or a queue. The default owner budget is 1 GiB, with a 128 MiB audio-file cap and 2 MiB artwork cap. Downloads run sequentially with progress, cancel, retry, remove and clear controls; no track is silently evicted. Successful native files are checked locally for playability; an unsupported saved file is retried as WAV. Authentication failures do not trigger compatibility retries. A retained authenticated session can play local files without the network; sign-out clears that member's downloads. iOS uses Application Support; tvOS uses purgeable Caches, so Apple TV downloads may need saving again. Cached manifests contain metadata and local filenames, not stream URLs or tokens.

The player shows lyric source and timed lyrics when supplied; selecting a timed line seeks playback. Buffered playback applies manual gain or album/track normalization with peak limiting. It retains only bounded current/next-track PCM at 48 kHz stereo and schedules gapless transitions on the native audio clock, with crossfade choices **Off**, **3**, **6**, or **12 seconds**. Sources outside the buffering budget or decoder support fall back to streaming with an explicit source-loudness label; normalization and crossfade are unavailable on that path. The sleep timer stores an owner-scoped deadline, and interruptions or headphone removal pause local playback.

**Audio output** discovers Sonos speakers and offers compatibility mode. The local player pauses after an acknowledged handoff; speaker status, transport and debounced volume controls use the server's output ticket. Returning playback requires acknowledgement of the remote stop. Local normalization, crossfade, repeat and sleep options are unavailable while Sonos owns output. These implementations do not establish every format, hardware output, seamless transition or complete web-feature parity; see the qualification scope in [verification](docs/verification.md).

## Playback behavior

Direct playback is negotiated for native MP4/M4V/MOV H.264 (8-bit)/HEVC (up to 10-bit) and AAC/AC-3/E-AC-3/MP3/ALAC. MP3 and ALAC additions have synthetic macOS AVPlayer decode evidence; per-device output qualification is still required. Other sources use the server's HLS path when supported. **Convert to compatible video** disables direct playback and asks the server for a compatible stream; the server may retain compatible video while converting audio. Conversion does not promise source HDR, Dolby Vision, lossless audio, or Atmos preservation.

The player seeks to the saved whole-file position before reporting start, sends progress about every five seconds and on transport state changes, and sends a final stopped event on dismissal. Reports are serialized so a delayed progress request cannot overwrite the stopped position. Leaving the app pauses video; music continues in the background. Stopping also releases the server's HLS session. A network failure displays a progress-sync warning. The audio engine schedules native file segments with bounded priming instead of allocating whole source/converted PCM buffers or copying a seek slice. Normalization, the existing stereo engine output and clock-scheduled crossfade remain active. Remote playback in queues with qualified source codecs, admitted metadata, crossfade off and unity effective gains use a private progressive range loader and AVQueuePlayer, starting before complete delivery. The engine and its gain units are created only when processing is needed. Enabling crossfade or a non-unity normalization gain switches that occurrence to the engine while retaining position; its bounded input still downloads completely and stays private until its prepared slot is released. Ordinary music pause/resume retains the current native player or prepared file slots without resolving, downloading or converting the track again; the app playback clock and decoded engine are paused. Stop, track replacement, sign-out and terminal failure release these resources. Music keeps an owner-scoped local queue checkpoint and exposes synchronization conflicts when the server becomes reachable. Active progressive playback controls read-ahead using native buffered time, with a reserve for queued-track preroll. Source position comes from the native player clock. Pausing suspends progressive HTTP read-ahead for the current and queued track; resume retains both assets. A paused seek permits only the current asset to fetch needed bytes until seeking completes.

The TV music player opens on full-screen artwork with a bottom timeline and a persistent Queue / Play-Pause / Repeat / Stop rail. Left and Right while artwork owns focus change queued tracks; Down enters the rail and lower options. Lyrics and listening options start collapsed. Hardware Play/Pause remains available, and Back unwinds the queue or player before leaving its browsing context.

Apple TV uses the native focus engine, remote transport controls, a readable poster grid, and native playback controls, following Apple's [tvOS design](https://developer.apple.com/design/human-interface-guidelines/designing-for-tvos), [focus](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection), and [video playback](https://developer.apple.com/design/human-interface-guidelines/playing-video) guidance. AVKit's preferred display criteria are enabled for the system's Match Content behavior. Actual HDR, refresh-rate switching, HDMI output, and multichannel sound must be checked on hardware; simulator playback cannot establish them.

Native icon/top-shelf assets and internal TestFlight packaging are included.
