# ADR 0034: Retain native artwork in a private device cache

The owner requested fast, visually complete Library returns and persistent on-device artwork with an explicit clear control. iOS and tvOS retain validated compressed artwork in a disposable 2 GiB device cache, alongside bounded decoded and compressed memory tiers, rather than refetching visited posters after memory eviction or every app launch.

Disk work runs off the main actor. File names hash the complete signed rendition URL, including its artwork tag and requested size; raw signed URLs and credentials are not written into cache metadata. An LRU index bounds storage without rescanning the directory after every write. Corrupt entries are discarded and fetched again. The OS may reclaim cache files. The cache directory is excluded from backups and uses platform file protection where supported.

Initial restoration of the same session may reuse its disk renditions. Actual member, server or credential changes discard resident artwork and invalidate pending disk writes before purging prior cache data. Device settings show retained bytes and provide an asynchronous Clear artwork cache action on both platforms. Clearing cancels old work so a late response cannot recreate deleted files. This cache stores visual renditions, not playable downloads or credentials, and never grants access to server media.

The Library retains a bounded set of in-process query snapshots, including loaded pages, cursors and alphabet anchors. The store owns the current query and shares repeated requests for it, so cancellation of a view's appearance task during navigation cannot strand the previous category on screen. A newer query or session change still cancels obsolete work. Explicit refresh and account/activity changes obtain fresh server state. Returning to a pushed Library root preserves its visible artwork and navigation identity; fresh walls prepare a viewport of images before publication. This trades local storage and bounded RAM for fewer requests and avoids exposing a partially repopulated grid during navigation. It adds no server schema or full-library background backfill.


## Amendment: complete native poster catalogs (2026-10-28)

The iOS and tvOS video walls opt into a complete lightweight catalog for empty-search Movies, Shows, Anime and combined video queries. `/Items?Fields=LuminaCatalog` retains ordinary member visibility, sort/filter predicates, total and absolute offsets, but projects poster identity, artwork tags, year, hierarchy, runtime and member state. It omits descriptions, people, sources and backdrop detail, and does not warm hero framing while enumerating. Ordinary detail reads remain complete. Older servers can ignore the projection and still return compatible items, with larger payloads.

The first 50 records publish promptly; one query-owned task drains subsequent 500-record pages without waiting for the scroll boundary. Query/session changes cancel obsolete work; suspension stops it and foreground activation resumes from the retained cursor. Failures retain loaded items and expose the existing retry path. Search, episodes and saved-provider channels keep ordinary pagination. Alphabet navigation into a loaded catalog scrolls within the retained A–Z wall. Retained query snapshots have both an eight-query and a 10,000-record aggregate ceiling; the active lightweight catalog itself scales with library size.

The wall renders the complete loaded metadata through the existing lazy grid. Only its initial viewport gates artwork readiness; later metadata batches do not stage or duplicate the entire array. Visible-poster changes replace a directional lookahead: at most 72 requested 400-pixel renditions on iOS and 36 requested 480-pixel renditions on tvOS. TV requests match the server's poster bucket instead of requesting an oversized original. Four shared artwork loads, the 128 MiB decoded cache target, 32 MiB compressed memory tier and 2 GiB disk cache remain in force. Mounted views release image references on disappearance. This avoids decoding or downloading every poster merely because its metadata is loaded. Cold-network poster readiness and physical-device fling smoothness still require measurement; a complete catalog does not guarantee every unseen poster has arrived.


## Amendment: decode at the requested width (2026-10-29)

The shared decoder applies the URL's requested width after accounting for image orientation, while retaining the 1920-pixel edge and 12 MiB encoded-response ceilings. Both network and disk reads use this budget, including an original returned in place of a rendition. Loading all catalog records therefore does not imply decoding every poster at hero resolution. Background suspension and memory warnings trim disposable RAM and speculative work on both native platforms; private disk renditions remain reusable.

The [TV qualification record](../../apple/docs/tvos-performance-2026-10-29.md) covers source-specific scores, remote playback, full-catalog navigation, and a 503-title synthetic memory workload. It records cache targets separately from whole-process footprint and does not claim physical-device energy or cold-network fling guarantees.

On iOS, backgrounding and memory warnings also invalidate decoded artwork held by mounted views, including a Library root retained behind a pushed detail. Hidden views release their local image references without reloading; visible artwork rehydrates from the existing cache when active or when it reappears, even if its URL is unchanged. Ordinary navigation keeps its warm-return behavior. This lifecycle policy does not change tvOS artwork retention.

## Amendment: private browsing metadata and TV shelf artwork (2026-10-29)

Native stores now retain small Home, detail, related-title and season/episode snapshots in a separate disposable device cache. It composes the existing bounded disk byte store in `LuminaMetadata`, with a 32 MiB disk ceiling, an 8 MiB encoded-memory target, 128 resident records and a 1 MiB/2,000-item per-record ceiling. JSON encoding/decoding and disk I/O run off the main actor. Keys hash the server, member, credential and resource; snapshots contain media DTOs, never request headers or session credentials. The same directory/file protection, backup exclusion and generation-safe clearing rules apply as for artwork.

TV browse reads opt into two-minute detail/season/related snapshots. Default reads and mutations remain fresh; metadata-editor revisions change the cache key, member-state mismatch bypasses a cached item, and explicit Home/activity refresh invalidates detail snapshots. Home can seed its last authorized-session shelves from snapshots for up to 24 hours, then always requests current shelves. This is presentation caching, not offline authorization or playback storage. Playback preparation and permission checks still use their existing server/download authorities. Actual account, server or credential changes invalidate resident data and pending writes before removing old snapshots. The full lightweight Library still uses its existing query-owned catalog and bounded in-process snapshots; this does not persist an unbounded catalog or introduce background full-library reads.

Portrait TV tiles resolve the series poster (or the explicit catalog-artwork override) for episodes, independently of the landscape episode still and hero's series backdrop. TV shelf posters request 480-pixel renditions, matching the catalog wall, rather than 760-pixel originals. The focused shelf warms at most eight upcoming renditions through the existing four-load artwork queue and cache budgets; focus changes replace speculative work. Changing the presentation never changes the playable item's identity.
